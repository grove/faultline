Found two suspected bugs and one test-protection gap.

**1. A configured default can unexpectedly trigger a prompt**

- **What could go wrong:** After `lookup_default` supplies a configured value, [Option.consume_value](/SNAPSHOTS/r2/src/click/core.py:3285) includes `DEFAULT_MAP` among sources that trigger prompting. An unattended command with `prompt=True` can therefore wait for input or abort at EOF.
- **Why these tests may miss it:** [test_flag_default_map](/SNAPSHOTS/r2/tests/test_defaults.py:105) never enables prompting. The nearby [prompt tests](/SNAPSHOTS/r2/tests/test_termui.py:407) never supply a default map.
- **Smallest useful test:** Invoke an option declared with `prompt=True`, supply `default_map={"name": "configured"}`, and provide empty stdin. Assert successful completion, the configured value, source `DEFAULT_MAP`, and no prompt.
- **Confidence and uncertainty:** **Suspected implementation bug; high confidence against the documented contract.** [The docs explicitly say default maps bypass prompting](/SNAPSHOTS/r2/docs/prompts.md:129). An intentional behavior change would require revising that contract.

**2. Missing public lookups expose `UNSET`**

- **What could go wrong:** [Context.lookup_default](/SNAPSHOTS/r2/src/click/core.py:698) returns `UNSET` for both an absent map and a missing key. Extension code checking `is None` would skip its fallback. [Parameter.get_default](/SNAPSHOTS/r2/src/click/core.py:2281) can likewise return the sentinel when neither default exists.
- **Why these tests may miss it:** No direct `lookup_default` assertions were located. [The callback test](/SNAPSHOTS/r2/tests/test_context.py:184) checks sentinel hiding through `ctx.params`; [the invocation test](/SNAPSHOTS/r2/tests/test_commands.py:262) uses a caller that explicitly converts `UNSET` to `None`.
- **Smallest useful test:** Parameterize absent maps and missing keys, with both `call` settings, and assert the intended public missing-value result—apparently `None`. Separately check a parameter with no declared default.
- **Confidence and uncertainty:** **Suspected compatibility bug; medium confidence.** [Context.invoke explicitly calls `UNSET` an implementation detail](/SNAPSHOTS/r2/src/click/core.py:803), supporting the expectation. However, `lookup_default`’s docstring does not explicitly define its missing-value result, and historical behavior cannot be established from this snapshot alone.

**3. Callable map defaults lack direct lazy-evaluation protection**

- **What could go wrong:** Eager evaluation during `call=False` lookup or help generation could perform configuration work or raise an exception merely while displaying help.
- **Why these tests may miss it:** [Map-help coverage](/SNAPSHOTS/r2/tests/test_options.py:572) uses a static string. [Dynamic-help coverage](/SNAPSHOTS/r2/tests/test_options.py:617) uses a parameter-local callable, leaving the map lookup branch unexercised.
- **Smallest useful test:** Put a counting factory in `default_map`. Assert that `lookup_default(..., call=False)` and `get_default(..., call=False)` return that exact factory without calling it, and help generation leaves the count at zero. A normal lookup should return its result and increment the count once.
- **Confidence and uncertainty:** **Missing test protection; high confidence.** The [public `call` contract](/SNAPSHOTS/r2/src/click/core.py:702) is explicit; the current implementation appears to honor it.
