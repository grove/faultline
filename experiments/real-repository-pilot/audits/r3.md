Found three gaps in test protection. The source currently follows the [documented initialization order](/SNAPSHOTS/r3/docs/init.md:509); static review did not establish an implementation bug.

**1. The conversion-order test stops before validation**

**What could go wrong:** An initializer regression could validate an earlier field before a later field has been converted, breaking validators that inspect other attributes.

**Why these tests may miss it:** [test_convert_before_validate](/SNAPSHOTS/r3/tests/test_make.py:1824) raises inside the first converter. It never observes successful validation or a later conversion. The docs demonstrate same-field conversion and cross-field validation separately, but do not combine them. The production boundary is the [validator block after the attribute loop](/SNAPSHOTS/r3/src/attr/_make.py:2386).

**Smallest useful test:** Give both `x` and `y` converters using `int`, and give `x` a recording validator. Construct with `"1", "2"`; assert the validator receives integer `1` and sees integer `instance.y == 2`. Record events to require both conversions before validation. A companion case where `y` conversion raises should record no validator calls.

**Confidence and uncertainty:** High-confidence missing test protection. The reviewed implementation preserves this boundary.

**2. Factory tests do not require earlier conversion to finish**

**What could go wrong:** Batching factories ahead of conversions could silently change dependent defaults. With `x="4"`, `converter=int`, and a later factory returning `self.x * 2`, the factory could produce `"44"` instead of `8`.

**Why these tests may miss it:** [test_converter_factory_property](/SNAPSHOTS/r3/tests/test_make.py:1803) uses a factory independent of the instance. [test_factory_takes_self](/SNAPSHOTS/r3/tests/test_dunders.py:866) only returns the instance itself. The [dependent-default test](/SNAPSHOTS/r3/tests/test_functional.py:352) reads an earlier field without a converter. None checks their interaction.

**Smallest useful test:** Declare `x` with `converter=int`; declare `y` with `Factory(lambda self: self.x * 2, takes_self=True)` and `converter=int`. Construct with `x="4"` and assert `(x, y) == (4, 8)`.

**Confidence and uncertainty:** High-confidence missing test protection, supported by the documented per-attribute factory/converter sequence and the [current generation logic](/SNAPSHOTS/r3/src/attr/_make.py:2316).

**3. Hook-order tests omit the validation boundary**

**What could go wrong:** Moving post-init before validation could run registration or other side effects for an instance whose constructor subsequently fails.

**Why these tests may miss it:** [test_pre_post_init_order](/SNAPSHOTS/r3/tests/test_make.py:917) has neither converters nor validators. Its [validation fixture](/SNAPSHOTS/r3/tests/test_make.py:66) toggles validation, but there is nothing to validate. The generated-class strategy also supplies [empty hooks](/SNAPSHOTS/r3/tests/strategies.py:171).

**Smallest useful test:** Record pre-init, conversion, validation, and post-init events. Convert `"-1"` to `-1`; have validation raise a sentinel exception. Assert that exception propagates and the events are exactly `pre-init, conversion, validation`, with no post-init event.

**Confidence and uncertainty:** High-confidence missing test protection. The source currently [places post-init after validation](/SNAPSHOTS/r3/src/attr/_make.py:2396).
